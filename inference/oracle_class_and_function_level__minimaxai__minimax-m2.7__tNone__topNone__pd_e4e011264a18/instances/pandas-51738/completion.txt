

Looking at the code, I need to optimize `Index.is_unique` to avoid unnecessary computation after slicing. The key insight is that if an index is strictly monotonic (either increasing or decreasing), it is guaranteed to be unique. By checking monotonicity first, we can short-circuit the more expensive hash table uniqueness check.

Let me implement the optimizations:

1. For the base `Index` class in `pandas/core/indexes/base.py`
2. For `IntervalIndex` in `pandas/core/indexes/interval.py`

    def is_unique(self) -> bool:
        """
        Return True if the IntervalIndex contains unique elements, else False.
        """
        left = self.left
        right = self.right

        if self.isna().sum() > 1:
            return False

        if left.is_unique or right.is_unique:
            return True

        seen_pairs = set()
        check_idx = np.where(left.duplicated(keep=False))[0]
        for idx in check_idx:
            pair = (left[idx], right[idx])
            if pair in seen_pairs:
                return False
            seen_pairs.add(pair)

        return True
