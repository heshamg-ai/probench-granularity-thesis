

Looking at the code, I can identify several optimization opportunities for the `QuantileRegressor.fit` method when using highs-family solvers:

1. **Redundant computations**: Computing `self.quantile * sample_weight` and `(1 - self.quantile) * sample_weight` separately when we could compute one and derive the other.

2. **Matrix construction**: For sparse matrices, using `np.eye` and converting to sparse is wasteful when `sparse.eye` is available directly.

3. **Dense matrix construction**: Using `np.concatenate` creates intermediate arrays. Pre-allocating and filling in-place is more efficient.

4. **c vector construction**: Using `np.concatenate` with multiple arrays can be optimized by pre-allocation.
