Looking at the `quantile` method, I can identify several optimization opportunities:

1. **Avoid re-computing `na_label_for_sorting` per block**: The `ids.max() + 1` computation and the `np.where` call for `labels_for_lexsort` are computed inside `blk_func` but depend only on group info that's the same for all blocks. Moving this outside avoids redundant work per column.

2. **Avoid redundant `isna` calls**: For numpy arrays that are already float64, `isna` is called to compute `mask`, but we can use `np.isnan` directly which is faster. Also, `needs_i8_conversion` is called twice - once for `mask` computation and once for the `is_datetimelike` check.

3. **Early type-based fast path**: For the common case of float64/float32 numpy arrays with linear interpolation, we can skip the expensive pre/post-processing entirely and compute quantiles directly.

4. **Avoid double allocation for 1D case**: When `vals.ndim == 1`, `out` is allocated as `(1, ngroups, nqs)` then immediately reshaped. For the scalar quantile case (`nqs == 1`), we can use a 2D output and skip the reshape.
