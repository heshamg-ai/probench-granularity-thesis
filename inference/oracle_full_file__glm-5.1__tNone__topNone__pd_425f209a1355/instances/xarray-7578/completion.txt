Looking at the `DatasetRolling.construct` method, I can see two key optimization opportunities when using stride on Datasets without indexes:

1. **Avoiding redundant stride application**: The current code calls `DataArrayRolling.construct` which internally applies `.isel({d: slice(None, None, s) for d, s in zip(self.dim, strides)})` for each data variable. Then at the Dataset level, the same `.isel()` is called again on the entire Dataset, causing double striding. We can avoid this by passing `stride=1` to each `DataArrayRolling.construct` call.

2. **Avoiding expensive index alignment on `.isel()`**: When a Dataset has no indexes for the rolling dimensions, calling `.isel()` at the Dataset level triggers index construction and alignment. Instead, we can apply the striding directly to each variable's data using `variable.isel()`, which is a lightweight operation that simply slices the underlying array without any index handling.

These changes eliminate redundant computation and the overhead of index materialization for non-indexed dimensions.
