

Looking at the `replace_list` method, I can see a key optimization opportunity. For numeric data types, the current implementation iterates through each replacement pair sequentially, creating masks one at a time. This is O(n*m) where n is data size and m is number of replacements.

I can optimize this for numeric data by:
1. Using `np.isin` to find all matching values at once (vectorized)
2. Using `np.searchsorted` or vectorized indexing for O(n + m) replacement
