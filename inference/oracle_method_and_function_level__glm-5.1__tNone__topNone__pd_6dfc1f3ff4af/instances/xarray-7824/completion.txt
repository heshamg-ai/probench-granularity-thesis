Looking at the `_dataset_concat` function, there are several performance bottlenecks when processing datasets with many variables:

1. **Inefficient `get_indexes` function**: The `get_indexes` generator is called via `list(get_indexes(name))` for every variable in `concat_over`. For each call, it iterates over *all* datasets, which means for N variables and M datasets, it does N*M iterations. However, only coordinate variables (in `coord_names`) can have indexes. By hoisting the index collection out of the loop and pre-computing it once, we reduce this to M iterations.

2. **Redundant `merge_attrs` calls in `get_indexes`**: Even when no indexes are found (the common case for data variables), `merge_attrs` was being called unconditionally for every variable. This is extremely slow when there are many variables and many datasets.

3. **Inefficient `ensure_common_dims` generator**: The generator uses `pd.unique` on a list comprehension which builds a list. This can be replaced with a `dict.fromkeys()` approach, which preserves insertion order and avoids building an intermediate list.

4. **Suboptimal variable lookup**: Inside the main loop, `ds[name]` and `ds.variables[name]` are called for every dataset. Looking up variables in `ds._variables` (a dict) directly avoids the overhead of the `__getitem__` property access.

5. **Redundant attribute merging for concat variables**: Attributes are merged once in `concat_vars` (which calls `merge_attrs`), and then if no index is found, they were being merged again in the `else` branch before being passed to `reindex_variables`. We can skip the second merge by reusing the attributes already computed in `combined_var`.
