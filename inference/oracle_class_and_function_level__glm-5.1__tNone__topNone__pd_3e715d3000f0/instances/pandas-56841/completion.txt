Looking at the optimization request, I need to optimize `DataFrame.join` for sorted joins where one side is unique. The key optimization target is the `_join_monotonic` method in `Index`, which already handles both-unique cases efficiently but falls back to `_left_indexer` when only one side is unique.

For a **left join with many:1 (right unique)**:
- The result index equals the left index
- Right indexer maps left → right positions
- Left indexer is just `np.arange(len(self))` (identity mapping)
- We can use `_left_indexer_unique` which is O(n log m) instead of `_left_indexer` which is O(n+m) with more memory allocation

For a **right join with 1:many (left unique)**:
- Same optimization, just swapped

This avoids allocating the join index array and the left indexer array in `_left_indexer`.
