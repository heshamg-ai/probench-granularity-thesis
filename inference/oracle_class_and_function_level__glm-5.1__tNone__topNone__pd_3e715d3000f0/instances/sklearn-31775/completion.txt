Looking at the call chain from `median_absolute_error` with `sample_weight`:
1. `median_absolute_error` calls `_averaged_weighted_percentile(xp.abs(y_pred - y_true), sample_weight=sample_weight)` — note `percentile_rank` defaults to 50.
2. `_averaged_weighted_percentile` calls `_weighted_percentile(array, sample_weight, percentile_rank, xp=xp) - _weighted_percentile(-array, sample_weight, 100 - percentile_rank, xp=xp)`. For `percentile_rank=50`, this is `_weighted_percentile(array, ..., 50) - _weighted_percentile(-array, ..., 50)`.

In `_weighted_percentile`, the most significant performance bottlenecks are:
1. **Double sorting**: `xp.argsort(array, axis=0)` creates a full index array, then `sorted_weights = xp.take_along_axis(sample_weight, sorted_idx, axis=0)` and later `sorted_nan_mask = xp.take_along_axis(xp.isnan(array), sorted_idx, axis=0)` both use this index array. Sorting `array` directly would be cheaper than argsort, and we can compute the sorted weights and NaN mask in one pass.
2. **NaN mask allocation**: `xp.isnan(array)` creates a full boolean mask even when no NaNs exist.
3. **Per-feature searchsorted in a Python loop**: `xp.stack([xp.searchsorted(...) for feature_idx in range(...)])` iterates over features in Python, which is slow. For 1D arrays (the case from `median_absolute_error`), this is especially wasteful.

The optimization:
- Sort `array` directly instead of `argsort`, and reorder weights/NaN in a single loop.
- Compute the NaN mask inline during the reordering loop, avoiding the large `xp.isnan(array)` allocation.
- Vectorize the `searchsorted` across features (works for both 1D and 2D), removing the Python loop.
- Add a fast path for 1D arrays that avoids the 2D reshaping, tiling, and stacking overhead.

This preserves exact semantics since the same sorting, CDF computation, and searchsorted logic is used.
